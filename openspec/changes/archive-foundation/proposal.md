## Why

The archive now has three strong surfaces (home, Código, Imaginario), but the rest of the system still duplicates navigation, Imaginario still lacks editorial metadata and sequential reading, and the 16 large photos load at full size. Renames and route migrations have already required manual edits across several files; the next section work should not repeat that. This change builds the foundation the remaining sections need.

## What Changes

- Add a single `_data/navigation.yml` source of truth for section names, URLs, glyphs, descriptions, primary visibility, and detail prefixes.
- Make the home hero nav, the home "Umbrales" index, the 404 explore links, and the detail back button read from that data.
- Complete Imaginario: populate `captured`, `place`, and `medium` where the archive notes state them; add previous/next navigation and arrow-key navigation; keep `image` as the poster/thumbnail for every plate.
- Add responsive image delivery for the Imaginario contact sheet: 480w and 960w WebP derivatives with a JPEG fallback, `srcset`/`sizes`, and a repeatable generation script.
- Add a quality gate: a dependency-free internal link checker over `_site`, wired into the existing GitHub Actions workflow.
- Keep the reading sections (Rastros, Poemas, Melange) as a separate follow-up design change; this change deliberately does not redesign them.
- No server-side 301 redirects: the existing client redirects stay as they are.

## Capabilities

### New Capabilities

- `site-navigation`: one navigation dataset drives primary section links, the closing index, 404 exploration, and detail back links; renames and route changes update in one place.
- `imaginario-archive`: Imaginario plates expose optional capture/place/medium metadata and sequential previous/next navigation without requiring every plate to be a photo.
- `image-delivery`: the contact sheet serves responsive WebP derivatives with a JPEG fallback and stable layout dimensions, generated by a repeatable script.
- `quality-gates`: the build runs an internal link check so renamed routes and broken references fail before deploy.

### Modified Capabilities

None. These are new capabilities.

## Impact

- `_data/navigation.yml` (new), `index.md`, `404.html`, `_includes/back-button.html`.
- `imaginario/index.md`, `_layouts/imagen.html`, `assets/css/style.css`.
- `content/collections/_images/*.md` (metadata only), `assets/media/images/*` (new derivatives).
- `scripts/` (image variants and link checker), `.github/workflows/jekyll.yml`.
- `admin/config.yml` stays compatible; no CMS field removals.
- No changes to the home canvas, Código runner, or the reading templates.
